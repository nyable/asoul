# asoul 国际化（i18n）规范

本文档是 asoul 全部用户可见文案的**单一事实来源**。新增功能、修改文案、修复界面时必须遵守本文，并同步维护 `internal/i18n/en.go` 与 `internal/i18n/zh_cn.go`。

---

## 1. 适用范围与例外

### 1.1 必须国际化
所有最终呈现给用户的文本，包括但不限于：

- TUI：tab、表头、列表单元格、状态/来源徽章、空状态、页脚、帮助、通知（`m.notice`）、错误（`m.err`）、模态标题与提示、输入框占位符、按钮提示；
- CLI：运行时输出（`out.Println/Printf/Successf/Errorf/Warnf/Infof`）与结构化结果中的人类可读字段；
- 体检诊断（doctor）、差异视图（diff）、部署结果等跨层共享的展示文案。

### 1.2 明确例外（不国际化）
- `internal/config/wizard.go`：首次运行向导在用户选择语言**之前**执行，刻意同时输出中英文，**禁止**改为 `i18n.T`。
- 品牌名、协议名、命令名：`asoul`、`Git`、`OpenCode`、`Claude`、`JSON`、`SKILL.md`、`catalog.json` 等。
- 机器可读载荷：文件路径、URL、哈希、枚举契约值（见 §2.4）。
- cobra 的命令帮助：`Use`、`Short`、`Long`、`Example` 与 flag 描述**保持英文**（CLI 帮助文本稳定，便于脚本与检索）。

## 2. 分层原则

```text
app 层（业务逻辑）      语言无关：结构化数据 + 英文规范值（JSON 契约）
        │
        ├── TUI 展示层    i18n.T(key, args...) 按当前语言渲染
        └── CLI 展示层    文本输出 i18n.T(key, args...)；JSON 使用 app 的英文规范值
```

### 2.1 app 层保持语言无关
- `internal/app`、`internal/deploy`、`internal/catalog` 等业务包**禁止** import `asoul/internal/i18n`。
- 需要本地化的结构化结果（如 `app.CheckItem`）同时携带：
  - 英文规范值（`Name`/`Message`）：作为 JSON 契约与兜底；
  - 翻译键与参数（`NameKey`/`NameArgs`/`MessageKey`/`MessageArgs`，`json:"-"`）。
- 展示层通过辅助函数渲染：有 key 走 `i18n.T`，否则回退英文规范值。

### 2.2 展示层负责翻译
- TUI 在渲染时调用 `i18n.T`；CLI 在输出文本时调用 `i18n.T`。
- 展示层不得把翻译后的字符串回写到业务数据或状态文件。

### 2.3 JSON 契约稳定
- `--json` 输出的键与人类可读值必须与界面语言无关，始终为英文规范值。
- 新增 JSON 字段前先评估兼容性；不得让 JSON 内容随 `config.language` 漂移。

### 2.4 枚举与状态值的两条通道
- **逻辑通道**：`model.ManagedStatus`、`model.UpstreamStatus`、`model.SourceType` 的底层字符串是内部契约，**不得**直接渲染给用户。
- **展示通道**：渲染必须经 `i18n.T("status.managed.clean")`、`i18n.T("upstream.status.up_to_date")`、`i18n.T("source.type.git")` 等键。

## 3. 键命名与组织

### 3.1 命名规则
采用层级命名法 `<domain>.<area>.<item>`，全小写、下划线分词：

| 域 | 用途 | 示例 |
| --- | --- | --- |
| `app` | 应用标题 | `app.title` |
| `tab` | 顶级 Tab | `tab.channels`、`tab.system` |
| `table.header` | 表头 | `table.header.check_item` |
| `empty` | 空状态 | `empty.skills`、`empty.doctor` |
| `footer` | 页脚快捷键 | `footer.doctor` |
| `help` | 帮助页（按页面） | `help.nav`、`help.page.channels` |
| `notice` | 通知/进度/结果 | `notice.updated_skill` |
| `confirm` | 确认弹窗 | `confirm.remove_skill.title` |
| `modal` | 模态文案 | `modal.add.title`、`modal.new.placeholder` |
| `diff` | 差异视图 | `diff.no_differences` |
| `detail` | 详情卡片 | `detail.label.name` |
| `dashboard` | 概览页 | `dashboard.card.health_title` |
| `doctor` | 体检诊断（键+值、CLI 输出） | `doctor.check.git`、`doctor.msg.projects_none`、`doctor.cli.title` |
| `status.managed` | 受管状态徽章 | `status.managed.clean` |
| `upstream.status` | 上游状态徽章 | `upstream.status.update_available` |
| `source.type` | 来源类型徽章 | `source.type.git` |
| `settings` | 设置页 | `settings.item.workspace` |
| `deploy` | 部署选择 | `deploy.group.managed_title` |
| `progress` | 进度条与阶段文案 | `progress.percent`、`progress.phase.receiving` |
| `target` / `model` / `tag` / `filter` / `loading` / `search` / `error` / `cli` | 对应功能域 | `cli.doctor.title` |

### 3.2 措辞规范
- 同一概念在所有位置使用**同一键**；不得为相同文案创建多个键。
- 新增键必须**同时**加入 `en.go` 与 `zh_cn.go`，键集合必须完全一致。
- 禁止拼接翻译片段组成句子。确需可选后缀时，使用独立片段键 + 收尾键，例如：

```go
summary := i18n.T("doctor.msg.consistency_total", total, clean)
if modified > 0 {
    summary += i18n.T("doctor.msg.consistency_modified", modified)
}
summary += i18n.T("doctor.msg.consistency_close")
```

- 占位符统一使用 `%d` / `%s` / `%v`；不得在翻译值里出现未声明参数的动词。
- 图标与 emoji 可以放在翻译值内，但不得用作**唯一**语义（须有文字）。
- 中文标点使用全角（`（）`、`，`、`：`），英文使用半角；收尾括号由独立键控制时，两语言各用各自形式。

## 4. 终端排版规范（与 `doc/TUI交互约定.md` 配套）

- 表格列对齐**禁止** `fmt.Sprintf("%-Ns", s)`；必须使用基于显示宽度的 `padCell(s, width)`（`internal/tui/table.go`）。
- 任何可能包含中文或 ANSI 的宽度计算必须使用 `lipgloss.Width` / `padCell`。
- 英文与中文文案长度差异大，布局必须预留弹性空间与安全截断（`truncate.StringWithTail`），不得用固定 80 列假设。

## 5. 测试规范

1. **显式初始化语言**：测试涉及视图断言时，必须在用例开头调用 `i18n.Init("en")` 或 `i18n.Init("zh-CN")`，不得依赖环境变量或上一个用例的残留状态（推荐 `defer i18n.Init("en")`）。
2. **中英双语覆盖**：关键界面至少覆盖英文与中文各一次，断言两种语言的实际输出。
3. **断言用可见文案**：断言优先匹配 `i18n.T` 的实际值或两语言任一，禁止依赖原始枚举值或未定义的占位串。
4. **自动化守卫**（`internal/i18n/*_test.go`）：
   - 字典键集合一致性（en 与 zh 必须相同）；
   - 代码中所有 `i18n.T("字面量")` 的键必须存在（根除 raw-key 泄漏）；
   - 除 `internal/i18n/`、`internal/config/wizard.go` 与 `*_test.go` 外，`internal/`、`cmd/` 的字符串字面量不得包含中日韩字符（AST 扫描，避免注释误判；测试用例因需断言本地化输出而豁免）。
5. **回归用例**：文件安全、权限、并发、TUI 交互与该文档相关修复必须附带针对性回归用例。

## 6. 变更清单（Definition of Done）

新增或修改任何用户可见文案时，同一提交内必须完成：

- [ ] 文案走 `i18n.T`，键按 §3 命名；
- [ ] `en.go` 与 `zh_cn.go` 同时更新（含所有占位符参数）；
- [ ] 若涉及按键/交互，同步更新 `footer.*`、`help.page.*` 与 `README.md` 键位说明；
- [ ] 相关展示层测试通过（中英双语）；
- [ ] 运行 `gofmt -w`、`go test ./...`、`go vet ./...`、`go build -o /tmp/asoul-build ./cmd/asoul`；
- [ ] 若涉及状态枚举渲染，确认未直接输出内部契约值。

---

## 7. 已落实的维护边界

- `app` 层技术性错误（如 `config manager not initialized`）当前保持英文；如需面向用户本地化，应通过**错误码 + 展示层包装**实现，而不是让业务层 import i18n。
- `--json` 输出的人类可读字段保持英文规范值；界面语言只影响交互式文本。
- `internal/config/wizard.go` 的双语输出为刻意设计，守卫扫描豁免。
