# asoul TUI 焦点层级交互约定

本文档是 TUI 按键行为与视觉呈现的**单一约定来源**。新增或修改任何按键、tab、模态交互时，必须遵守本文，并同步更新页脚/帮助文案。

---

## 1. 核心模型：焦点层级

TUI 把可横向导航的控件组织成**焦点层级（focus depth）**：

```text
depth 0  一级栏（顶级 Tab）
depth 1  二级栏（当前页的子 tab / 渠道 / 筛选模式）
```

任意时刻只有一个层级处于**聚焦**状态，由 `Model.focusDepth` 表示。按键的作用域由焦点层决定，而不是由"先二级、再穿透一级"的隐式规则决定。

**不变量**：横向键只在当前聚焦层内活动，绝不跨级；层级切换键（`Tab` / `Shift+Tab`）只改变聚焦层级，不改变一级 Tab。

---

## 2. 键位规则

### 2.1 主界面

| 键 | 行为 |
| --- | --- |
| `←` / `→`（`h` / `l` 为别名） | 仅在当前 `focusDepth` 内循环：depth0 循环一级 Tab，depth1 循环当前页二级。**绝不跨级** |
| `Tab` | 当前页存在二级时在层级间**循环**（depth0 → depth1 → depth0）；无二级页按键允许但无变化 |
| `Shift+Tab` | 同 `Tab` 的循环（仅两级时与 `Tab` 等价）；无二级页无变化 |
| `Esc` | depth1 时退回 depth0；否则维持原语义（清搜索 → 清选择 → 无动作） |
| `1`-`9` / `m` / `s` | 直达一级 Tab，`focusDepth` 复位为 0，二级复位到第一项 |
| `[` / `]` | 仅 depth0 时一级前后循环；depth1 时 no-op |
| `↑` / `↓`（`j` / `k`） | 列表光标移动，与焦点层无关 |
| `PgUp` / `PgDn`、`g` / `G` | 列表/视口滚动，与焦点层无关 |
| `/` | 进入搜索 |
| `i` | 打开当前选中对象的详情（上游 / 技能 / 渠道行 / 项目） |
| `I` | 打开当前页面上下文对象：Channels=当前渠道，Settings=初始化工作区 |
| `Enter` | 主列表**不绑定任何动作**；仅在模态内作为确认 / 提交 |

### 2.2 查看详情统一键（硬约束）

「查看详情」只有一组规范键，禁止在各页面自造：

| 键 | 含义 |
| --- | --- |
| `i` | 当前**选中对象**的详情：Sources=选中上游；Skills(技能子标签)=选中技能；Channels=当前高亮行（供应商头→供应商详情，模型行→模型详情）；Projects=选中项目 |
| `I` | 当前**页面上下文对象**的详情：Channels=当前渠道完整详情（路径、特性、已部署技能）；Settings=为当前工作区初始化 `catalog.json` |

- 主列表 `Enter` 不再承担详情或默认动作；详情、跳转、编辑、开关分别由 `i` / `I`、`e`、`Space` 等键负责。
- 旧别名一律移除：上游的 `Enter`/`Space`、技能的 `Enter`、项目的 `Enter`/`v`、模型行的 `Enter`/`Space` 都不再打开详情。
- 模态内部的 `Enter` 语义不变（确认 / 提交 / 弹窗内动作），不受本约束影响。
- Settings 页无「详情对象」，故该页 `i` 无动作，`I` 复用为初始化；这是唯一例外。

### 2.3 模态与弹窗

模态统一采用同一焦点模型，每个模态声明一个有序的**焦点组**：

- `←` / `→`：在当前焦点组的选项卡内循环；
- `Tab`：循环到下一个焦点组（如表单字段、筛选行 → 下一组），末尾回到第一组；
- `Shift+Tab`：循环到上一个焦点组，第一组回到末尾；
- 仅有一个焦点组时按键允许但无变化。

### 2.4 文本输入例外（硬约束）

焦点落在**文本输入控件**内时，`←` / `→` 归属输入框（移动光标），焦点层**不得拦截**。字段间移动只能用 `Tab` / `Shift+Tab`。

## 3. 进入与复位

- 所有改变 `activeTab` 的操作（`←/→`、数字直达、设置页跳转）必须经过统一入口 `setActiveTab()`。
- `setActiveTab()` 负责：设置一级 Tab → `focusDepth = 0` → 二级复位到第一项（Targets→Agent，Models→渠道 0）。
- 二级不跨页面记忆：每次进入都从第一项开始。

---

## 4. 视觉规范

每个可横向导航项有四种状态：

| 状态 | 样式 | 说明 |
| --- | --- | --- |
| 聚焦 | 紫色 `activeTabStyle` / `subTabFocusedStyle` | 当前正在导航的那一层 |
| 上级 | 淡紫 `ancestorTabStyle` | depth1 时，一级 Tab 作为上级锚点 |
| 选中 | 蓝色 `subTabSelectedStyle` | depth0 时，二级当前选中项（可见但不聚焦） |
| 普通 | 灰色 `inactiveTabStyle` / `subTabInactiveStyle` | 其余项 |

有二级的页面**始终渲染两行**：第一行一级 Tab，第二行当前页二级。当前具备二级的页面：Channels（渠道切换）、Skills（技能/分组）、System（缓存/诊断）。

一级 Tab 文案不含编号，编号由渲染层按顺序拼接（`N. 名称`），增删页面无需改动文案。

窄终端（`width < 110`）降级：一级显示单 pill `◀ 4. Channels ▶`，二级行各自单 pill，`◀ ▶` 归属当前聚焦层。

### 4.1 固定头脚与内容滚动（硬约束）

- 一级 Tab 栏（含搜索栏）**固定渲染在首行**，页脚与通知行固定在底部，任何页面都不允许把它们顶出屏幕。
- 内容区在「终端高度 − 固定头脚」的剩余高度内滚动；每个列表页的可见行数由 `Model.listRows/N` 统一计算，不得再写死 `m.height - N`。
- 列表溢出时渲染 `more.*.above/below` 指示行；诊断页（System > Diagnostics）支持 `↑`/`↓`、`PgUp`/`PgDn`、`g`/`G` 滚动，选中项始终可见。
- 非 TTY/未知高度（`height <= 0`）时不做裁剪，保持原有输出用于测试。

### 4.2 等待与进度反馈（硬约束）

- 所有会阻塞界面的操作必须进入统一的 loading 状态（`Model.loading`），由加载弹窗或模态内的加载区展示同一套进度组件。
- 有可靠计数的操作必须显示进度条与百分比，格式为 `[████░░░░] 50% (100/200)`；计数来源是 `internal/progress.Update`。
- 无可靠计数的操作显示动画旋转符与流动条（marquee），**不得**展示伪百分比。
- git clone/fetch 等工具输出由 `internal/gitx` 解析为结构化 `progress.Update`；可解析出 `n/m` 的显示真实百分比，否则回退为阶段名或原始行。
- 进度条、明细与阶段文案统一经 `internal/i18n`（`progress.*`）渲染；`internal/app` 与 `internal/progress` 禁止输出本地化文案。
- 动画帧由 `progressTickMsg` 驱动，仅在 `Model.loading` 为真时推进；业务层不得自行启动计时器。
- 操作结束或 `Esc` 取消后必须调用 `finishLoading()` 清理 loading、进度与取消句柄，迟到消息不得覆盖新状态。

---

## 5. 模态通用约定

- 确认：`Enter` / `y`；取消：`Esc` / `n`。
- `q`：仅在主列表退出应用；任何模态内 `q` 一律等同 `Esc`（关闭/返回），防止误退。
- `Space`：勾选/切换。禁止使用 `"space"` 作为键名（bubbletea 中空格是 `" "`）。
- 破坏性操作后的确认弹窗必须同时提供 `Esc`/`n` 取消路径。

---

## 6. 页脚与帮助维护

- 页脚（`internal/i18n/*.go` 的 `footer.*`）只列出当前页的高频快捷键，不再重复 `Tab` / 方向键等层级切换说明；层级导航统一由帮助页承载。
- `?` 打开**当前主页面的独立帮助页**（`help.page.*` + 共享 `help.nav`）。帮助内容必须可滚动（`↑`/`↓`、`PgUp`/`PgDn`、`g`/`G`），`Esc` / `?` / `q` 关闭，样式为标题 + 段落高亮。
- 详情键只允许 `i` / `I`（见 2.2）；页脚、帮助页 `help.page.*` 与 README 不得再把 `Enter`/`Space` 等描述为列表详情键。
- 页脚、模态 hint、帮助页 `help.page.*` 与 `README.md` 的键位说明必须与本文及实现保持一致。文案键规范见 [`doc/i18n规范.md`](./i18n规范.md)。
- 修改按键时，上述文案必须在同一提交内同步更新。

---

## 7. 测试要求

针对 TUI 交互的改动，至少覆盖：

1. depth0 按 `←/→` 只改变一级 Tab；
2. depth1 按 `←/→` 只改变二级且 `activeTab` 不变；
3. 无二级页 `Tab`/`Shift+Tab` 无变化；有二级页连续 `Tab` / `Shift+Tab` 在 depth0/depth1 间循环；
4. 边界 no-op（如 Models 最后一个渠道、Targets Project 不再跳一级）；
5. 进入页面时二级复位到第一项；
6. 模态 `Tab`/`Shift+Tab` 在焦点组间双向循环。
